# Sketch3D kernel implementation plan

The maintainer resolved the Phase 0 decisions on 2026-11-25. Phase 0 experiments are underway. Owned fixtures define outcomes missing from the application tooling corpus. Martensite tracks the kernel capability in [#611](https://github.com/Oblikovati/Martensite/issues/611) and Oblikovati tracks desktop integration in [#4190](https://github.com/Oblikovati/Oblikovati/issues/4190).

- [SCENARIO-MAP.md](SCENARIO-MAP.md): the class and phase of each scenario.

## Scope and baseline

Sketch3D authors points and curves in model space, solves relations between them, and rebuilds curves that depend on earlier sketches or body geometry. Its outputs must survive a source edit and save and reopen. Downstream features can reference them as Sweep paths, Loft sections, or ordinary Extrude profiles when certified coplanar.

This assessment covers all 38 feature files and 242 scenario definitions in the MCAD-Scenarios `features/sketch3d` corpus pinned by [CORPUS.sha256](CORPUS.sha256), along with their functional, fixture and blocker notes. Of these, 71 state a result a kernel test can assert, 20 state snapshot isolation, 2 show a preview only, and 149 belong to the application alone. Many K results were captured visually and have no expected numbers yet.

`oblikovati-rust` owns the end-to-end scenarios and uses the corpus as a tooling reference. Martensite derives focused kernel fixtures from the geometry and edit contracts in those scenarios. The manifest records the 191 inputs used for this assessment (E6). Kernel acceptance runs against repository-owned fixtures with independent expected results.

The assessment inspected Martensite at [d4635266](https://github.com/Oblikovati/Martensite/commit/d463526642b7bf950ba33c7ab4a4c9bc97caffaf) and the wrapped sketch implementation at `1ef70ab2`. The wrapped implementation has since landed on `main` in [PR #610](https://github.com/Oblikovati/Martensite/pull/610) at `fb7dd57f`. Start implementation from current `origin/main`. The wrapped pipeline qualifies and sweeps authored profiles on selected cylinders and cones. Its ownership, tolerance, history and cancellation contracts carry over to the spatial sketch's edit and solve path.

The Rust app's `rust-work` snapshots (`4d35f6551` and `1f5db9d56`) contain a document-owned `SpatialSketch` point and line recipe (`crates/model/src/spatial_sketch.rs`). They also contain a Corliss-based Inventor reader and projection helper (`crates/persistence/src/inventor_spatial.rs`, tracking `#4092`). Desktop Inventor interop is pending. `SpatialSketch::new` currently accepts degenerate lines with identical endpoint IDs (`endpoints[0] == endpoints[1]`). `oblikovati-solve` provides automatic differentiation, pivoted QR, nonlinear solving, residual scaling, preference solves and freedom diagnostics. The app's typed expression and units layer (`crates/model/src/expression/`) handles formula parsing and unit binding.

The inspected app snapshots pin older Martensite revisions (`bef25f47` at `4d35f6551` and `0e72f866` at `1f5db9d56`). They do not depend on `martensite-tksketch` and have no Sweep feature (E5). The app integration branch starts from `4e46aba91`, which pins Martensite v0.14.2. The workspaces differ in MSRV (`1.98.1` in Martensite, `1.99.0` in `oblikovati-rust`, E3).

The legacy Go app is a source of documents and cases to examine. It is not an oracle because known defects affect it, such as the intersection curve in [Oblikovati #3317](https://github.com/Oblikovati/Oblikovati/issues/3317) (E7).

The main source entry points at `d4635266` are [TKSketch](../../../crates/martensite-tksketch/src/lib.rs), [curve interpolation](../../../crates/martensite-tkgeomalgo/src/geom_api/interpolate.rs), [BRep section](../../../crates/martensite-tkbo/src/brep_algo_api/section.rs), [directional projection](../../../crates/martensite-tkbool/src/brep_proj/projection.rs), [helix builder](../../../crates/martensite-tkhelix/src/helix_brep/builder_helix.rs), [contour extraction](../../../crates/martensite-tkhlr/src/contap/mod.rs) and [planar profile extrusion](../../../crates/martensite-tkbo/src/profile_extrusion/mod.rs). App entry points are `crates/model/src/spatial_sketch.rs`, `crates/persistence/src/inventor_spatial.rs`, `crates/model/src/expression/mod.rs` and `crates/solve/src/lib.rs`. The kernel links resolve on `d4635266`; an older local checkout does not contain every file.

## Solver gaps

The candidate core (`oblikovati-solve`) needs these changes before a spatial caller uses it. E2, E3 and E8 hold the evidence.

| Gap | Required change or rule |
| --- | --- |
| Dense Jacobian/QR and global-width `DualNumber` gradients (E2, E3). Drag p95 is 3.95 to 5.56 ms at 60 vars and 26.4 to 28.3 ms at 120. | Seed `DualNumber` over each block's local variables (3 to 12) and scatter into a sparse or block-structured Jacobian. Partition connected components, exploit block sparsity, and eliminate fixed or identity-merged variables where provenance permits. |
| `solve_with_preference` takes undamped full tangent steps with no backtracking and nests full LM solves per outer step (E3). | Add trust-region or line-search backtracking on the preference step and amortize or couple the tangent and restoration steps so curved 3D drags (arcs, chains, `On Face`) do not stall. |
| Single global `model_scale` across length and `(u, v)` variables; row-only scaling in `analyze_structure` (E3). | Separate variable-domain scaling for length coordinates and surface `(u, v)` parameters, and base length scaling on component extent instead of distance from the origin. Add column equilibration to rank diagnostics so NURBS UV domains and far-from-origin sketches do not lose conditioning or misreport rank. |
| No mid-solve frame-refresh or continuation hook (E3, E8). | Support a retryable pole-guard signal when `\|r·u(d)\| > 0.9` in smooth-frame relations so the solver refreshes `r` and resumes without leaving the manifold. |
| Redundancy scan takes 103 to 106 ms at 120 vars when one row is redundant (E2). | Run after commit, outside drag updates. Replace one factorization per source with a rank-revealing update or dependency certificate. |
| Any redundant row gives `OverConstrained` (E3). | Use full-rank rows with ADR-0034 shared-endpoint elimination. Report convergence, redundancy, conflict and freedom as separate facts. |
| No bounds or inequalities (E3). | Solve unbounded on periodic lifts and refuse by trim classification. Use the [owned trim-boundary fixture](OWNED-FIXTURES.md#imports-attachment-drag-and-cross-sketch-references) to determine whether an active set is needed. |
| No direct constructor for a value with kernel derivatives (E3). | Add a checked derivative-injection interface for curve and surface evaluations and fit-point spline linear operators. Cross-check against finite differences and analytic derivatives. |
| Zero-length derivatives use a zero-gradient convention (E3). | Detect refused sets (including `Angle` iterate `u1 ∥ u2` and zero tangents) before differentiation. |
| Go-derived constants, fixtures and MSRV mismatch (E3). | Record source revisions, check known defects, replace expected values with independent oracles, and verify MSRV `1.98.1`, `missing_docs`, `cargo deny --all-features check` and `cargo audit`. |

## Kernel contracts

- Put the spatial edit and solve API in `martensite-tksketch3d` (D3). Keep `martensite-tksketch` for surface-bound sketches. Put the approved shared numerical core in a low-level crate below the app and sketch crates if X1 passes. Use TKMath for numeric bounds, TKBRep to capture support and trim occurrences, TKGeomAlgo to evaluate captured geometry, and TKTopAlgo for topology traversal and classification. Keep section ancestry in TKBO. Compose section and projection above these toolkits. Freeze public interfaces alongside their first consuming path.
- Use typed entity, endpoint, relation and source-occurrence identities. Carry explicit `PointRole` (`Defining`, `SketchMarker`, `CenterMarker`) and deletion/pruning closure matching app ADR-0017. Capture external inputs by revision, location, orientation and parameter domain; external sketches and model occurrences are read-only to the current solve. The kernel reports correspondence and all parents; the app owns persistent names (ADR-0021), feature order, undo/redo transactions and last-valid-result policy.
- Keep edits pure functional: `(Snapshot, Edit, Tolerances, WorkControl) -> Result<EditOutcome, EditError>`, returning an immutable `Send + Sync` snapshot, changed entities, relation state, validation evidence and history. Distinguish completed-empty, incomplete, cancelled, inconsistent and invalid outcomes. Scope preview state to the base revision and discard superseded previews. Plumb cancellation through every operation, including `tkhelix` and pipe-shell adapters. Keep no global or thread-local mutable algorithm state anywhere in the path.
- Warm-start dirty connected components with deterministic variable and equation order. Keep fixed variables hard and pointer targets as preferences. Validate accepted values independently of solver convergence, including frame-free vector invariants, branch checks and minimum lengths. Run four-stage ordered validation for publication (topology, geometry consistency, self-intersection, tolerance consistency), with local checks on changed entities during interactive edits. Keep spatial, parameter, angular, modelling and approximation tolerances distinct. Expose explicit tolerance-cap modes (`no-limit`, `report`, `refuse`; never default to `no-limit`) and report requested limits, effective or clamped settings and measured error (tagged certified, sampled or unknown) separately.
- Share bounded incidence and trimmed-face queries across attachment, trim, section and projection. Preserve curve intervals, orientation, parameter correspondence and periodic lifts. Use analytic tests or bounded refinement for modeling decisions and keep tessellation in presentation. Detect overlaps explicitly and refuse exhausted work when a required check remains inconclusive.
- Export eligible spatial curves as immutable `Send + Sync` wires with stable occurrence identities, orientation and consistent vertex tolerances. Check continuity, closure and self-incidence for each consumer. Sweep accepts a Sketch3D path, including eligible nonplanar chains. Loft accepts ordered Sketch3D sections that meet its section contract. Both resolve sketch revisions and preserve source correspondence on rebuild.
- Lower a closed loop to `tkbo::profile_extrusion` after fitting a plane, certifying out-of-plane deviation within the declared tolerance cap, projecting to nondegenerate plane `[u, v]` coordinates and checking `ProfileCurve` admission. Follow the constraints in [#390](https://github.com/Oblikovati/Martensite/issues/390) and [#494](https://github.com/Oblikovati/Martensite/issues/494). The selected-support normal extrusion from #610 uses its own input contract.
