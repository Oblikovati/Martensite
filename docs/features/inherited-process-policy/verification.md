# Verification for inherited cases

The case-runner unit controls use a named installer that records and refuses
every call. Direct and prepared inherited cases complete with zero calls.
Preparation and body errors retain their typed causes and leave completion
absent. Finite and inherited requests refuse each other's records; an unknown
request header and an invalid identity also refuse.

Live controls execute the registered test in a separate process. They check
that the application report remains0 and that the parent retains the bound
schema2 receipt, entry and completion witnesses. Unix controls install a finite
OS CPU limit in the child before entry and compare both soft and hard limits
inside the body. A prepared control checks the existing OS policy and its owned
preparation value.

Run the affected package and its documentation tests with:

```sh
cargo test --locked -p martensite-process-policy --features case-runner
```

The Unix resource-limit controls compile only on Unix. Windows executes the
portable lifecycle, installer and fresh-child controls. Platform CI establishes
the supported targets; a Linux execution alone provides no macOS or Windows
runtime evidence. The existing finite-case controls remain part of the suite.
