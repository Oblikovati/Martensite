# Process CPU-budget termination

Bug #278 restored the existing promise that an expired process budget prints its declared diagnostic and exits with code 2. A CPU cap had been installed without its signal action, so the operating system terminated the process with a signal instead. The elapsed watchdog already kept the promised behavior.

The foundation OS adapter now owns the CPU request, signal action and resource update. Process-policy delegates through a safe interface and retains its existing public API. There is one atomic requested value. Setters serialize outside the signal action; they publish that value before lowering a cap, so a limit that expires immediately can report the new request. A refused OS update deliberately retains the requested value and its typed I/O cause. The reported request can therefore differ from the effective OS limit after refusal. Signed `Some` values retain the existing cast to the host unsigned resource domain; `None` requests an unlimited cap. Separate direct-OS and policy children compare the signed edge cases on each platform. Successful concurrent updates leave the two values coherent.

The signal action is installed before the resource cap. It reads only the atomic value, formats at most 20 decimal digits in a fixed stack buffer, writes the diagnostic and calls `_exit(2)`. It allocates no memory, takes no lock and runs no destructors. SIGPIPE is blocked only while this CPU action runs, so a closed output pipe cannot replace exit code 2; the process-wide SIGPIPE disposition remains unchanged. The existing foundation signal-action builder handles platform layouts. Standard Rust has no signal-installation API; the existing checked resource wrapper does not supply a signal exit action. The small FFI boundary stays in the foundation's approved OS module and adds no dependency.

This configuration changes the whole process. Callers own restoration and per-operation deadlines. The elapsed watchdog interval and budgets are unchanged. CPU and elapsed expiry, concurrent worker exhaustion, an already-consumed CPU budget, reset, concurrent setters, OS refusal and a closed stdout pipe are tested in fresh children. The same 12-second parent safety guard bounds these tests. The fixed buffer also has independent decimal fixtures for zero, negative values and both i64 extremes.
