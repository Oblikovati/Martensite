# macOS CPU diagnostic safety

Bug #289 exposed two independent effects. Darwin records `FWASWRITTEN` after an ordinary write, so exact descriptor comparisons must bracket the resource setter after fixture writes finish. A failed pipe write sends SIGPIPE to the process. Blocking that signal in the diagnostic thread leaves other application threads able to receive it. XNU records these behaviors in [the write implementation](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/kern/sys_generic.c).

The macOS relay resolves its public process primitive and binds ordinary native calls before reporting readiness. Private socket pairs have `SO_NOSIGPIPE`; these sockets share no application open-file description. Changing `F_SETNOSIGPIPE` on a duplicated stdout would change the caller's shared file description, as shown by [XNU's descriptor implementation](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/kern/kern_descrip.c).

Only terminal CPU expiry creates a writer process. The signal action sends the signed request and one absolute 100-millisecond grace deadline. The regular relay calls the public `vfork` primitive. The caller exits with code 2 independently of the relay's progress. Neither initialization nor a refused initialization creates a child, so an application that continues has no helper zombie to reap.

Apple documents full-fork semantics without application `pthread_atfork` callbacks [from macOS 12 onward](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/man/man2/vfork.2). The API is deprecated and can refuse an invocation. LibSystem still performs its own fork housekeeping; its code can allocate and synchronize before returning to the child. The implementation relies on that platform primitive and claims no mathematical bound on its internal progress.

After the primitive returns, the child uses native calls and checked stack storage. Its alarm belongs only to that child. The child refuses expired or oversized grace values, and checks whether its original parent is still present. It enumerates its own actual descriptor table, closes every handle except current stdout and the private reply socket, then attempts the bounded message. A failed, malformed or truncated inventory ends the attempt before stdout is written. The fixed array holds 4096 records; a larger native table returns an overflow error. A lowered open-file limit does not bound already-open descriptor numbers.

The writer reports its actual I/O outcome through the private stream. Its one-shot timer is due at the same absolute grace deadline; operating-system scheduling can delay delivery and cleanup. The relay distinguishes a complete reply from an incomplete stream. The caller never signals or waits on a helper PID. Application SIGCHLD policies and application reapers retain their ownership; after terminal exit the operating system reaps any remaining child. The writer ends with `_exit`, bypassing copied application destructors.

Diagnostic output remains best effort. If the CPU signal interrupts a thread holding a loader or allocator lock, the regular relay can remain inside the platform primitive until the caller exits. An unavailable diagnostic still requires exit code 2. A complete write, a refused spawn and a pending operation are separate observations.

Verification separates those claims. Controlled recipients retain exact message, real refusal and callback-bypass assertions while concurrent fixture workers block only SIGXCPU. Separate stress cases leave application workers unmasked and verify termination, unchanged caller policies and explicit incomplete output evidence. That recipient configuration belongs only to tests. Cleanup checks hold a stdout pipe full until the last writer closes, observing HUP before any drain. The original four product regressions retain their assertions and 12-second safety guard.

## CPU-budget support on macOS

CPU budgets require macOS 12 or newer (Darwin 21 onward), as approved for #289. Older or malformed releases return a typed `Unsupported` initialization error before changing the resource cap. A missing public symbol also returns `Unsupported`. This requirement applies to CPU budgets; other kernel features retain their existing operating-system support. Deployment targets and package versions are unchanged.
